### Дипломная работа: Агрометеорологическое веб-приложение
>Репозиторий: github.com/ArseniiMaiorov/AppBackup
Клиент-серверное веб-приложение информационной поддержки
сельскохозяйственной деятельности на основе интегрированных
агрометеорологических данных.

**Технологический стек:**

Интерфейс пользователя построен как одностраничное приложение (SPA) с использованием современного стека, ориентированного на сложное состояние и интерактивную карту.

Серверная логика и API вынесены в отдельный микросервис на основе Python.

Нейросетевая обработка и загрузка данных занимают много времени, все тяжелые задачи вынесены в отдельный обработчик.

Система полностью контейнеризирована для воспроизводимости и простоты развертывания.

Подсистема машинного обучения и анализа данных работает на стеке Python-библиотек.


1. Клиентская часть (Frontend)
    * Фреймворк: Vue 3. Выбран за зрелость экосистемы и удобство создания реактивных интерфейсов.
    * Управление состоянием: Pinia. Используется для централизованного хранения состояния приложения. Данные разделены на тематические сторы (например, для карты, для полей, для задач, для погоды), что упрощает отслеживание изменений и взаимодействие между компонентами.
    * Сборка и разработка: Vite (используется сервер разработки на порту 5173).
    * Картографический движок: В тексте упоминается работа с картой, слоями и тематическими данными (OSM, спутниковая подложка). Карта является центральным элементом интерфейса.
    * Интерфейс: Реализована концепция "рабочего стола" с независимыми перетаскиваемыми окнами.
    * Стилизация: светлая и темная темы оформления.

2. Серверная часть (Backend API)
    * Фреймворк: FastAPI. Выбран из-за асинхронной архитектуры (ASGI), что критично для I/O-операций (запросы к БД, внешним API), а также за автоматическую генерацию документации OpenAPI и встроенную валидацию данных через Pydantic.
    * Язык: Python 3.11.
    * Аутентификация: JWT (JSON Web Tokens). Access-токен живет короткое время и передается в заголовках, Refresh-токен хранится в HTTP-only Cookie для безопасности.

3. База данных и хранилище
    * Основная БД: PostgreSQL 15 с расширением PostGIS 3.4.
        * PostGIS критически важен, так как система активно работает с геометрией полей (полигоны, AOI, пространственные индексы GIST для быстрых запросов).
    * Кэш и брокер сообщений: Redis 7.
        * Используется как брокер для асинхронных очередей (Celery).
        * Служит для кэширования промежуточных состояний и статусов задач.

4. Асинхронный контур вычислений (Фоновые задачи)
    * Планировщик задач: Celery. Позволяет ставить задачи в очередь, не блокируя основной поток API.
    * Воркеры (Worker): Запускаются как отдельные процессы Python 3.11 + Celery для выполнения детекта полей, построения признаков и расчетов.

5. Инфраструктура и развертывание
    * Контейнеризация: Docker и Docker Compose. Все сервисы (Frontend, Backend, DB, Redis, Worker) поднимаются через один compose-файл.
    * Миграции БД: Alembic (инструмент для SQLAlchemy), используется для версионного управления схемой базы данных.

6. Математическое обеспечение и ML-контур
    * Геообработка: Библиотеки для работы с растровыми данными (подразумевается использование GDAL, Rasterio, NumPy) для построения стеков спектральных индексов (NDVI, NDWI и др.).
    * Нейросети: Модель сегментации BoundaryUNet v3 CPU.
        * Для оптимизации вычислений на CPU, модель сконвертирована в формат ONNX (Open Neural Network Exchange), что позволяет делать инференс быстрее без GPU.
        * Используются библиотеки для работы с тензорами (PyTorch или ONNX Runtime), а также стандартные инструменты для загрузки данных и аугментации.
